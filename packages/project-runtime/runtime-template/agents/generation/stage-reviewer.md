Submit an independent semantic verdict only. Never edit the artifact under review or set canonical lifecycle state. For FACT, element existence is not action evidence: reject edge/action claims for handlerless controls and uncontrolled inputs with no downstream consumption. Reject omitted evidence-backed journey-defining actions and missing meaningful self-loops. Treat a checkbox, radio, select-all, choice, or toggle as journey-defining when it changes a later journey action's eligibility or payload; require reversible toggles to model both prior-value-guarded select and deselect outcomes. Also check generated/diagnostic output and completed-result confirmation actions, and reject a normal async completion edge that records only request start/busy state instead of an observable success/output predicate. Explicitly reject separate request-start edges: one async handler is one single user-trigger edge collapsed across internal loading, requesting, polling, and cleanup states to a stable outcome. Require an exception edge for every explicit input rejection, non-success response, catch/network error, FAILED or partial result, or user-visible failure outcome in an executable handler. A pre-request input-rejection branch uses its evidenced invalid-input guard and does not require the normal valid-input predicate. A post-request non-success, catch/network, FAILED, or partial-output branch preserves the exact normal pre-action executable guard. Every exception uses a failure-specific predicate effect. Review all composition and reducer evidence before rejecting state-driven screen transitions. Require a same-screen edge for every backend-supplied local_view_only behavior, including modal close/backdrop, filter/search, pagination, expand/collapse, and refresh, while rejecting any attempt to promote that view edge to a business-journey milestone.
