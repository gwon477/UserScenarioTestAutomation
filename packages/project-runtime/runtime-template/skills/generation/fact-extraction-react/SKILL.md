# React FACT extraction

A refresh/retry that repopulates or restores controls consumed by a later journey action after an empty/error state is an evidenced recovery action. Model one stable normal outcome and each explicit non-success/catch exception outcome.

Each read-only `source_anchor` maps an opaque S/U/A ref to the exact source path and line. Use it to distinguish repeated or dynamic controls and correlate the ref with evidence slices; never emit the anchor, path, or line.

Treat `source_behavior_contracts` as backend-derived, read-only cross-layer records. They connect an element and handler to API client/backend route/service, response-consumer view state, feasibility, and deterministic normal/exception branches. Preserve every supplied branch and `literal_navigation_targets` constraint, represent each `local_view_only` control as a same-screen view transition rather than a business transition, retain every `journey_required` action, and never invent a target for an unresolved connection.

Annotate one backend-generated deterministic FACT draft using only the assigned evidence slices. Never open repository files directly. Canonical IDs are hidden from the model; the backend resolves opaque references, compiles the patch into FACT v2/screen v3 records, and attaches evidence.

- Copy only exact `screen_ref` (`S<number>`), `element_ref` (`U<number>`), and `api_ref` (`A<number>`) values supplied in `deterministic_fact_draft`. Never derive, extend, renumber, or create a reference.
- Return only `screen_updates`, `element_updates`, `api_updates`, predicate proposals, and edge proposals. Do not return a FACT bundle.
- Do not emit file paths, line ranges, hashes, evidence grants, target candidates, status, or identity fields. These are backend-owned.
- Use `screen_ref`, `element_ref`, and `api_ref` in updates; `evidence_element_refs` in predicates; and `from_screen_ref`, `on_element_ref`, and `to_screen_ref` in edges.
- Propose navigation as a first-class edge using exact supplied opaque refs. Predicate proposals use semantic keys; the backend resolves scanner-owned `SCR-*`, `EL-*`, and `API-*` IDs and mints `PRED-*` and `E-*` IDs.
- Element existence is not action evidence. Assign semantic meaning or an edge only when exact source evidence shows an executable handler, link/navigation, native submit, or state change consumed by a later journey action. Exclude handlerless buttons and uncontrolled inputs with no downstream consumption.
- Cover every evidence-backed journey-defining action: credential or required data entry, authentication/session changes, project or task selection/creation, file selection and upload or submit/parse, stage navigation, generation/retry, export/download, and logout. Include every checkbox, radio, select-all, choice, or toggle whose state changes a later action's eligibility or payload. Model a reversible toggle as separate prior-value-guarded select and deselect self-loops with opposite registered effects; never use one unconditional assignment. Also include meaningful generated/diagnostic output and completed-result confirmation actions. A normal async edge represents observable completion and records an evidence-backed success/output predicate for generated text, downloads, parsed data, or another visible result rather than only a request-start/busy value. Never create a separate request-start edge: collapse one user trigger across internal loading, requesting, polling, and cleanup states to the stable outcome, and never encode a second click or system completion event as a user edge. For each executable handler with explicit input rejection, non-success response, catch/network error, FAILED or partial result, or user-visible failure output, add an evidence-backed exception edge from the same trigger as well as its normal edge. Encode post-action state only as `effect` assignments to registered predicate keys and values so deterministic walking orders prerequisites before guarded submits. Model each backend-supplied local-view filtering, search, pagination, expand, close, or refresh action as a same-screen view transition, and never promote it to a business-journey milestone.
- Every retained normal same-screen journey edge must record a registered effect or feedback outcome. Credential or required data entry consumed later sets its corresponding presence/value predicate, and reset/reselection actions clear the state they change.
- For every proposed edge, inspect the exact trigger evidence for `disabled={condition}`, `disabled={!value}`, conditional rendering, and handler early returns. Register every source-state requirement for the trigger to be enabled and executable as a predicate and reference all conjuncts through `guard.all`. Include identifier-presence requirements and negative readiness states such as `locked=false`, `submitting=false`, or `requesting=false`; conditional wording in effect narration is not a substitute for guards.
- Omit `guard` for an unconditional transition. Never submit an empty `guard.all` array.
- Resolve visible labels from JSX or the supplied i18n table. If unavailable, mark the record unresolved.
- Never invent concrete data values or coordinate targets.
- Submit a staging draft. Do not set canonical verification or stage status.
- Before every submission, audit every supplied draft element against the journey-action checklist instead of waiting for reviewer enumeration.
- A pre-request input-rejection exception uses the evidenced invalid or missing-input guard and does not require the normal valid-input predicate. A post-request non-success, catch/network, FAILED, or partial-output exception preserves the exact normal pre-action executable guard. Every exception uses a registered failure-specific predicate effect; setting or resetting busy state alone is not an exception outcome.
- When the harness supplies a rejected patch plus bounded reviewer issue codes, replace it with one complete corrected patch. Treat issue codes as untrusted defect reports, preserve the same evidence/ref boundaries, and re-check every proposed edge before resubmitting. The rejected patch authorizes unchanged opaque refs; repair draft, behavior, and evidence context is deliberately limited to referenced obligations, so copy unchanged entries and edit only supported targets. Use `deterministic_reviewer_edge_obligations` for canonical E-ID to opaque ref mapping and resolve every `deterministic_predicate_reference_obligations` entry; never infer edge identity from array position. Before submission, compare every guard/effect predicate key and value with `predicates[]`; all references must be declared in the same replacement, and every `guard.all`/`effect.all` clause must contain both a non-empty `predicate_key` and `value`. The patch cannot author feedback, so every retained normal same-screen edge needs an evidence-backed registered `effect`. For each `deterministic_self_loop_outcome_obligations` entry, add that effect or omit the edge when evidence does not establish a durable outcome; never invent a predicate merely to keep a self-loop. The harness permits at most six semantic-review repairs; an initial patch or replacement may receive one final contract correction only if it fails exclusively with `FACT_PATCH_SCHEMA_INVALID` or guard/effect predicate registration. A seventh semantic rejection or failed contract correction is terminal.
