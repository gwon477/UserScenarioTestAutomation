## 2. 공수 수치의 산출 근거

장표의 `~115 MD`, `~30 MD`, `~74%`는 제가 대규모 SI 통합테스트를 기준으로 세운 **설계 기준 추정치**입니다. 실측이 아니므로 `~` 표기를 그대로 두었습니다. 제출 전에 아래 가정값을 현업 확인으로 보정하십시오.

**전제** — 대규모 SI 프로젝트의 통합테스트 1개 차수, 테스트 케이스 1,000건. 1 MD는 8시간으로 환산했습니다.

**As-Is · 건당 55분 → 114.6 MD**

| 활동 | 건당 | 환산 |
|---|---|---|
| 시나리오 작성·검토 (설계서와 화면을 보며 케이스·스텝 작성) | 25분 | 52.1 MD |
| 수행 (화면 조작, 테스트 데이터 준비 포함) | 12분 | 25.0 MD |
| 증적 캡처·문서화 (스텝별 캡처, 증적 문서 정리) | 18분 | 37.5 MD |
| **합계** | **55분** | **114.6 MD** |

**To-Be · 27.9 MD**

| 남는 사람 일 | 대상 | 건당 | 환산 |
|---|---|---|---|
| 생성된 시나리오 검토·확정 | 1,000건 | 8분 | 16.7 MD |
| NON_AUTOMATABLE 스텝 수동 수행 | 150건 (15%) | 10분 | 3.1 MD |
| 실패 케이스 원인 확인 | 250건 (25%) | 6분 | 3.1 MD |
| 초기 셋업 (소스 연결, 계정·데이터, 환경) | 차수당 1회 | — | 5.0 MD |
| **합계** | | | **27.9 MD** |

절감률은 (114.6 − 27.9) ÷ 114.6 = 75.6%입니다. 장표에는 보수적으로 올림해 **115 MD → 30 MD, 74% 단축**으로 적었습니다.

**심사에서 물어볼 지점과 답변 준비**

- "측정한 값인가" — 아닙니다. 실측은 실제 앱 2개의 6스텝 왕복 실행이고, 공수 수치는 케이스 1,000건을 가정한 산식입니다. 이 구분을 먼저 말하는 편이 안전합니다.
- "증적 18분이 과한 것 아닌가" — 스텝 5~8개짜리 케이스에서 스텝별 캡처와 문서 정리를 포함한 값입니다. 현업 실측으로 바꿀 수 있으면 그 값을 쓰십시오.
- "NON_AUTOMATABLE 15%의 근거" — 이 값이 가장 약합니다. 대상 시스템 성격에 따라 크게 달라지므로, 담당 프로젝트에서 세어 본 비율이 있으면 교체하십시오.
- "검토 8분이면 충분한가" — 생성 시나리오를 읽고 승인·수정하는 시간입니다. 초기 차수에는 더 걸리고 회차가 쌓이면 줄어든다는 점을 덧붙이면 됩니다.
