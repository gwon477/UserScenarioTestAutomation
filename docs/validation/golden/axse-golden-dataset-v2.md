# axse-agents 골든 데이터셋 v2

작성일 2026-09-18. 근거는 `test_project_source/axse-agents` 소스 직접 판독이며, ScenarioForge 산출물은 참조하지 않았다.

## 0. 작성 규칙과 독립성

- 이 문서는 **생성 결과를 보고 쓰지 않았다.** 평가가 순환하지 않도록 프런트엔드 `frontend/src`와 백엔드 `backend/app/api` 소스만 읽고 도출했다.
- v1(`test_project_source/axse-agents/SCENARIOFORGE_GOLDEN_DATASET.md`)은 픽스처 안에 있어 수정하지 않는다. 차이는 6절에 기록한다.
- `[확정]`은 소스에서 동작·guard·요청·상태 변화가 직접 확인되는 항목, `[추론]`은 사람용 업무명만 명명한 항목이다.
- 자격 증명과 식별자의 실제 값은 정의하지 않는다.

## 1. 화면 구조와 진입 게이트

`App.jsx`는 상태 두 개로 최상위 화면을 가른다. `[확정]`

```
!loginReady            → LoginFormPage   (로그인 폼)
loginReady && !sessionReady → LoginPage  (프로젝트 선택)
그 외                   → MainPage        (셸 + 단계 화면)
```

`MainPage`는 `Shell`이 지속 크롬(로그아웃·새로고침·홈·TS 작업 선택·좌측 nav)을 제공하고, `page` 상태로 단계 화면을 교체한다. 단계 화면은 UPLOAD, PARSED_DB(db), BUSINESS, SCENARIO, SETTINGS다. `[확정]`

### 단계 접근 게이트 `[확정]`

`main.page.jsx:30-34`, `1496-1518`

- `STAGE_ORDER = ["UPLOAD","PARSED_DB","BUSINESS","SCENARIO"]`
- 목표 단계가 `task.ui_stage`보다 **앞서거나 같으면** 화면만 전환한다.
- 목표 단계가 `ui_stage`보다 **뒤면** `PATCH /tasks/{id}/stage`로 서버 단계를 올린 뒤 전환한다.
- `taskId`가 없으면 단계 전환 자체가 동작하지 않는다.
- `settings`와 `preview` 전환, 그리고 `currentStage === "GENERATING_SCENARIOS"`일 때의 `scenario` 전환은 게이트를 우회한다.

## 7. 미해결

- 설정 화면의 `초기화`·`저장`·checkbox·select는 handler와 API가 없어 케이스로 승격하지 않았다. `settings.page.jsx` `[확정]`
- 로그인 백엔드는 현재 mock이며 실제 PIMS 연동 분기는 주석 처리돼 있다. 401·502 분기는 소스에 존재하나 현재 유발 불가라 `G2-SC-003`에 통합했다. `backend/app/api/v1/auth.py:29-60` `[확정]`
- 업무흐름 화면 수정(`PUT /business-flows/{id}/screens`)은 백엔드 라우트가 있으나 프런트엔드 호출부가 없어 케이스로 넣지 않았다. `[확정]`
