## PROBE-01 과의 차이

1. PROBE-01에서 토큰 한도로 못 돌린 **개선된 ground truth 추출기**로 다시 측정했다. 스크롤 컨테이너에서 잘린 요소를 제외하고, `aria-label` 대신 화면에 보이는 텍스트를 우선한다.
2. 자격증명이 교체됐다. 값은 환경변수로만 전달했고 어떤 파일에도 기록하지 않았다.
3. 네 조합(프로젝트 2 × 좌표계 2)을 모두 완주했다.

## 남은 실패의 실제 원인

768 좌표계에서 실패한 9건을 하나씩 확인했다. 그라운딩 정확도 문제는 1건뿐이다.

| 원인 | 건수 | 내용 |
| --- | --- | --- |
| **라벨이 화면에 보이지 않음** | 3 | `aria-label`만 있는 32x32, 24x24 아이콘 버튼. 모델이 읽을 글자가 없어 전부 `not-found`로 답했다. 추측하지 않았다 |
| **라벨이 렌더링된 텍스트와 다름** | 4 | 원장 날짜 셀의 DOM 텍스트는 `2026-08-21T09:12:00+09:00`이고 화면에는 잘린 날짜만 보인다. 모델은 보이는 「2026-08」을 읽었고, 같은 열 여섯 행 모두의 접두사여서 인접 행을 지목했다 |
| **접미사만 다른 반복 컨트롤** | 1 | `RA-2026-002 변경사항 반영`을 요청했는데 모델이 `RA-2026-001 변경사항 반영`을 지목하고 그 라벨을 그대로 보고했다 |
| **작은 대상** | 1 | AXSE `업무` 버튼 35x25px에서 30px 어긋났다. 라벨은 정확히 읽었다 |

즉 **비전 그라운딩 자체는 실용 수준이고, 실패는 대상 서술의 품질 문제다.**

## confidence 는 판별력이 없다

RA-DAR 768 기준으로 hit과 miss의 confidence 분포가 겹친다. 어떤 임계값도 둘을 가르지 못한다. PROBE-01의 관찰이 재확인됐다.

## Proposal Gate replay

기록된 64개 제안을 `packages/test-runtime`의 실제 gate에 통과시켰다. 이 결과는 `src/execution/proposal-gate-replay.test.ts`로 고정되어 있다.

| | AXSE | RA-DAR |
| --- | --- | --- |
| 대상 | 39 | 25 |
| 옳은 제안 통과 | 36 | 17 |
| **틀린 제안 통과(누락)** | **1** | **0** |
| 옳은 제안 차단(과차단) | 2 | 3 |

- 누락 1건은 35x25px `업무` 버튼이다. 라벨을 정확히 읽었으므로 라벨 대조로는 잡히지 않는다.
- 과차단 5건은 모두 **서술의 라벨이 화면에 보이지 않는** 경우다. 값이 채워진 뒤 사라진 placeholder 2건, `aria-label`만 있는 아이콘 1건, `select`의 옵션 전체 텍스트 2건이다. 화면에 없는 글자를 기대한 서술이므로 거부가 옳다.
- 잘린 날짜 셀과 인접 행 오지목은 전부 차단됐다.

## replay 가 찾아낸 gate 결함 두 개

replay로 실제 응답을 흘려보내면서 gate 규칙의 결함을 두 개 찾아 고쳤다.

1. **부분 일치를 무조건 허용하던 문제.** 「2026-08」은 「2026-08-21T09:12:00+09:00」의 접두사여서 통과됐고, 같은 열 여섯 행 어디에도 들어맞았다. 짧은 조각이 근거가 되지 않도록 일치 비율 하한(0.6)을 넣었다.
2. **장식 기호를 그대로 비교하던 문제.** 모델은 「↺ 새로고침」을 「↻ 새로고침」으로, 「RADAR」를 「RA · DAR」로 옮겨 적었다. 좌표는 1~8px 오차로 정확했는데 기호 차이로 거부됐다. 글자와 숫자만 남기도록 정규화를 바꿔 5건의 과차단이 사라졌다.

## 설계에 반영한 것

- `VisualTargetDescriptor.visibleLabel`을 **필수**로 바꿨다. 화면에 읽을 글자가 없는 대상은 비전 경로로 지목할 수 없다는 것이 실측 결과다. `target_candidates`는 사후 대조용이며 대상을 찾는 근거가 아니다.
- `VisualTargetDescriptor.labelUniqueOnSurface`를 추가했다. 같은 화면에 같은 라벨이 여러 개면 라벨 일치는 필요 조건일 뿐이며, gate는 후보 대조가 성공해야 통과시킨다(`TARGET_NOT_DISAMBIGUATED`).
- 컴파일러는 라벨이 중복이고 대조할 후보도 없으면 `AMBIGUOUS_VISUAL_TARGET`으로 사람 확인에 넘긴다.

## 생성 트랙에 대한 근거 강화

설계 §12의 「FACT element label의 화면 가시성 표시」 요청이 실측으로 뒷받침됐다. 과차단 5건과 `not-found` 3건이 모두 이 필드가 없어서 생긴다. 라벨이 화면에 보이는 텍스트인지, 잘려 렌더링되는지를 FACT가 표시해 주면 이 8건은 계획 단계에서 걸러진다.

## 한계

- 두 앱 모두 백엔드를 stub으로 대체했다. 실제 데이터 밀도와 행 수는 다를 수 있다.
- 화면당 최대 6개 대상, 1회 측정이다. 신뢰구간을 주장할 표본이 아니다.
- 단계 2 이후(실제 프레임 캡처 → 모델 왕복 → 입력 합성 → assertion 판정)는 실행하지 않았다.
- replay는 기록된 응답에 대한 재생이다. 실제 실행 루프에서의 gate 동작은 단계 2에서 확인한다.
