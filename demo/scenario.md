# 시연 시나리오: 소스 디렉터리 하나로 시나리오 도출부터 증적까지

## 사용자
분석 담당자. 대상 시스템의 로컬 소스 디렉터리를 ScenarioForge에 연결해 사용자 시나리오를 도출하고, 도출된 케이스를 실제 화면에 수행시킨 뒤 증적으로 판정 근거를 확인한다.

## 목표
새 프로젝트를 등록해 분석을 걸어 두고(장시간 작업), 이미 분석이 끝난 프로젝트에서 시나리오 확인 → 케이스 질의 → 테스트 실행 → 증적 확인까지 한 바퀴를 보인다. 실제 사용자가 쓸 수 있는 모든 기능을 한 편(약 240초)에 담는다.

## 성공 기준
시청자가 이 영상만 보고 프로젝트 등록부터 증적 확인까지 스스로 수행할 수 있다.

## 흐름
| # | 페이지 | 사용자가 하는 일 | 왜 이 순서인가 |
|---|---|---|---|
| 1 | 프로젝트 | 연결된 프로젝트와 요약 수치를 본다 | 제품의 단위가 소스 디렉터리임을 먼저 말한다 |
| 2 | 프로젝트 → 작업대 | 프로젝트를 추가한다 | 등록이 곧 작업대 진입임을 보인다 |
| 3 | LLM 연결 설정 | 모델과 API 키를 저장한다 | 등록 직후 요구되는 유일한 준비물 |
| 4 | 작업대(개요) | 4단계 파이프라인을 읽고 첫 단계를 실행한다 | 분석이 무엇을 만드는지 실행 전에 알린다 |
| 5 | 분석 진행 중 | 진행률과 세부 단계를 보며 기다린다 | 약 70분이 걸리는 작업임을 자막으로 알리고, 걸어 두고 떠나도 됨을 말한다 |
| 6 | 프로젝트 | 분석이 끝난 프로젝트(RA-DAR)를 연다 | "걸어 두고, 끝난 것을 본다"는 실제 사용 리듬 |
| 7 | 개요 → 생성 이력 | 회차별 결과를 열어 본다 | 산출물이 회차(run) 단위로 쌓임을 보인다 |
| 8 | 사용자 시나리오 | 업무 분류별 케이스를 읽고 단계·기대 결과를 펼친다 | 케이스가 화면 나열이 아니라 완결 여정임을 보인다 |
| 9 | 시나리오 질의 | 케이스를 질의 패널로 끌어 놓고 질문한다 | 산출물이 읽는 문서가 아니라 질의 가능한 정본임을 보인다 |
| 10 | 테스트 실행 | 실행별 케이스 판정을 보고 실패 실행을 연다 | 도출과 수행이 같은 케이스 ID로 이어짐을 보인다 |
| 11 | 테스트 수행 | 수행 대기열의 단계별 판정을 보고 증적을 연다 | 판정이 주장에 그치지 않고 근거로 이어짐 |
| 12 | 증적 상세 | 단계 타임라인, 캡처, 판정 근거를 읽는다 | 프레임과 좌표로 남는 판정 근거 |
| 13 | 증적 | 실행별로 묶인 증적을 판정·케이스 ID로 거른다 | 증적이 실행 단위로 관리됨을 닫는 말로 쓴다 |

## 다루지 않는 것
- 실제 LLM 호출과 실제 분석 산출물(브라우저 표본 데이터로 시연, 화면 배너에 표시됨)
- 검토자(reviewer) 모델 분리 설정, 저장된 키 삭제, 프로젝트 관리(경로 이동·삭제)
- Windows·모바일 대상 수행

## 오프닝 훅
"소스 디렉터리 하나면 시나리오 도출부터 테스트 증적까지 이어집니다" - 첫 자막이 시청자의 목표를 말한다.
